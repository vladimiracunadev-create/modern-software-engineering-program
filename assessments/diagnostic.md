# Diagnóstico integral

No tiene calificación. Responde con evidencia o marca “aún no”.

1. Convierte una necesidad ambigua en criterio verificable.
2. Explica una invariante y diseña un caso límite.
3. Describe cómo revisarías un cambio Git antes de integrarlo.
4. Distingue arquitectura lógica, runtime y despliegue.
5. Diseña un modelo de datos y una migración segura.
6. Explica biblioteca, framework y runtime.
7. Selecciona niveles de prueba para una transferencia de dinero.
8. Modela una amenaza de autorización por recurso.
9. Diseña rollback para código y para datos.
10. Define un SLO desde experiencia de usuario.
11. Propón una migración legacy reversible.
12. Define límites de autoridad para un agente de IA.

## Práctica

Elige un flujo de un producto canónico. Escribe requisito, contrato, modelo, prueba, amenaza, métrica y procedimiento de fallo. No necesitas implementar.

## Uso

Las respuestas determinan partes de entrada y desafíos de convalidación. Ningún puntaje permite omitir seguridad, recuperación o ética del proyecto final.
