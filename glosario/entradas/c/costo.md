## Definición

Define cuántas fronteras por segundo caben.

Es uno de los temas de [SE-287 — Taller: elegir y aislar un runtime para una carga no confiable](../../../classes/part-23-runtimes-y-plataformas-modernas/se-287-taller-elegir-y-aislar-un-runtime-para-una-carga-no-confiable/README.md), donde se enseña como «Costo».

## Por qué importa

En [SE-287 — Taller: elegir y aislar un runtime para una carga no confiable](../../../classes/part-23-runtimes-y-plataformas-modernas/se-287-taller-elegir-y-aislar-un-runtime-para-una-carga-no-confiable/README.md), el tema «Costo» importa porque define cuántas fronteras por segundo caben.

En [SE-372 — Proyecto: plataforma de datos mínima gobernada](../../../classes/part-30-ingenieria-de-datos-y-plataformas-de-datos/se-372-proyecto-plataforma-de-datos-minima-gobernada/README.md), el tema «Costo» importa porque la plataforma debe tener un costo estimado.

## Cómo funciona

Según [SE-372 — Proyecto: plataforma de datos mínima gobernada](../../../classes/part-30-ingenieria-de-datos-y-plataformas-de-datos/se-372-proyecto-plataforma-de-datos-minima-gobernada/README.md):

La plataforma tiene un costo que se estima con las fórmulas de `SE-370`: bytes leídos por consulta frecuente, frecuencia de refresco de cada conjunto, TB-mes por retención y duración del camino crítico. El registro de metadatos añade un campo de presupuesto por conjunto y el control, una regla futura: si la proyección mensual de un dueño supera su presupuesto, avisa. No se implementa aquí para no mezclar un parámetro inventado con una regla de gobierno; se declara como extensión.

## Ejemplo

Caso medido en la sección «El costo de cada candidato» de [SE-287 — Taller: elegir y aislar un runtime para una carga no confiable](../../../classes/part-23-runtimes-y-plataformas-modernas/se-287-taller-elegir-y-aislar-un-runtime-para-una-carga-no-confiable/README.md):

Medido en el taller y en `SE-282`: una instancia de Wasm con un módulo ya compilado cuesta unos 0,09 ms; cortar un bucle infinito por combustible tardó 27 ms (2 000 000 de unidades) frente a 629 ms con un proceso con límite de 0,5 s. Un proceso nuevo de Python cuesta entre unos 100 y 160 ms solo por arrancar. La consecuencia: Wasm permite una frontera por petición en el camino caliente; el proceso, una por tarea de segundos o minutos.
