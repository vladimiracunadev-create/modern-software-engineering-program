Definición

Componente reutilizable de un flujo de trabajo escrito por otra persona.

Definición de trabajo de SE-478 — Riesgos de CI y dependencias comprometidas.

Por qué importa

La clase donde se define, SE-478 — Riesgos de CI y dependencias comprometidas, existe con este propósito: la clase existe para que veas el sistema de integración continua (CI) como lo que es para un atacante: un lugar donde se ejecuta código con credenciales.

Cómo funciona

Según SE-478 — Riesgos de CI y dependencias comprometidas:

Registra síntoma, entrada mínima, hipótesis, observación que descarta cada hipótesis, causa, corrección y prueba de regresión. Síntoma: el registro del flujo muestra la salida de una orden que nadie escribió en el repositorio. Hipótesis rivales: (a) un compañero añadió un paso; (b) una acción de terceros imprime eso; (c) el título de la solicitud se interpoló en el comando. Prueba: busca en el archivo del flujo expresiones ${{ github.event... }} dentro de run; si la hay, y el texto del título coincide con la salida, la causa es (c). Conclusión: inyección de scripts por contexto no confiable. Regresión: pasa el dato por una variable de entorno, añade la regla al escáner y una mutación que la reintroduzca para comprobar que el escáner la detecta.

Ejemplo

La clase no ilustra este término por separado; el ejemplo de su tema está en la sección «Ejemplo profesional» de SE-478 — Riesgos de CI y dependencias comprometidas:

El flujo de publicación de la API de entregas se reescribe con cuatro reglas. Todas las acciones se fijan a un SHA y un trabajo semanal propone las actualizaciones como solicitudes revisables. El permiso por defecto es vacío y cada trabajo declara el suyo: las pruebas leen el contenido, la publicación escribe solo la etiqueta del release.

Errores y confusiones comunes

Las clases no registran un error exclusivo de este término. Los errores frecuentes del tema donde se enseña (SE-478 — Riesgos de CI y dependencias comprometidas) son:

  • Una acción cambia de comportamiento sin cambios en el repositorio — causa: referencia por etiqueta. Corrección: fijar a un SHA y revisar las actualizaciones.
  • Un título de solicitud ejecuta órdenes — causa: interpolación del contexto en run. Corrección: pasar el dato como variable de entorno.

Límites y cuándo no aplica

Las clases no fijan un límite propio para este término. Los límites del tema donde se enseña (SE-478 — Riesgos de CI y dependencias comprometidas) son: Las definiciones son operativas para la API de entregas. No convierten términos con una historia más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final. Se ejecutó un escaneo real de los tres flujos de este repositorio, un experimento de 155 mutaciones efectivas con semilla fija y un análisis de alcance, con resultados idénticos en Windows 11 (CPython 3.12.9) y Ubuntu bajo WSL2 (3.12.3).
