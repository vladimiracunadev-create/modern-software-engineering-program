Definición

Operación única que hace que el sistema use la versión nueva.

Definición de trabajo de SE-477 — Instaladores, paquetes y actualizaciones.

Por qué importa

La clase donde se define, SE-477 — Instaladores, paquetes y actualizaciones, existe con este propósito: la clase existe para que decidas cómo llega tu software al equipo de otra persona, qué ocurre cuando la instalación o la actualización se interrumpe y cuántas versiones distintas estarán en uso al mismo tiempo.

Cómo funciona

Según SE-477 — Instaladores, paquetes y actualizaciones:

La verificación ocurre sobre el directorio preparado y antes de la activación: se calcula la huella de cada archivo y se compara con el manifiesto firmado (SE-473). Si algo no coincide (una descarga corrupta, un byte alterado), el directorio se descarta y la instalación actual no se ha tocado. Tras activar, la aplicación arranca una comprobación de humo; si falla, se vuelve a apuntar a la versión anterior, que se conserva hasta que la nueva ha funcionado durante un plazo. La migración de datos y configuración del usuario es el punto delicado: debe ser reversible o hacerse sobre una copia, porque una migración que reescribe el archivo de configuración con un formato que la versión anterior no lee impide el retroceso (el mismo problema de SE-476, ahora sin servidor).

Ejemplo

La clase no ilustra este término por separado; el ejemplo de su tema está en la sección «Ejemplo profesional» de SE-477 — Instaladores, paquetes y actualizaciones:

El procedimiento de actualización de entregas-cli descarga el paquete y su manifiesto firmado a un directorio temporal dentro de la misma partición que la instalación, verifica la firma con la clave incorporada y la secuencia, calcula la huella de cada archivo, descomprime en versiones/2.0.0/, ejecuta la migración de configuración sobre una copia y una comprobación de humo (entregas --version y una subida de prueba a un entorno de ensayo) y cambia el puntero actual con un renombrado.

Errores y confusiones comunes

Errores que las clases asocian con este término (síntoma → causa → corrección):

  • El programa no arranca tras una actualización interrumpida — causa: archivos de dos versiones. Corrección: directorio nuevo y activación atómica. (SE-477)

Límites y cuándo no aplica

Las clases no fijan un límite propio para este término. Los límites del tema donde se enseña (SE-477 — Instaladores, paquetes y actualizaciones) son: Las definiciones son operativas para la API de entregas. No convierten términos con una historia más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final. Se ejecutaron cuatro experimentos: una inyección de fallos con archivos reales en un directorio temporal (resultado idéntico en Windows 11 con CPython 3.12.9 y en Ubuntu bajo WSL2 con 3.12.3) y una simulación de 20 000 clientes con semilla fija.
