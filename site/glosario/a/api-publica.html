Definición

La api incluye nombres, tipos, errores, efectos, orden, formato y comportamiento documentado que consumidores pueden depender.

Definición de trabajo de SE-110 — SemVer, compatibilidad y contratos públicos.

El programa usa el término con matices según la clase; el sentido principal es el anterior y los demás lo precisan:

  • En SE-474 — Versionado, compatibilidad y changelog: Conjunto de interfaces y comportamientos que un proyecto promete mantener.

Por qué importa

En SE-110 — SemVer, compatibilidad y contratos públicos, el tema «API pública» importa porque la API incluye nombres, tipos, errores, efectos, orden, formato y comportamiento documentado que consumidores pueden depender.

Cómo funciona

Según SE-110 — SemVer, compatibilidad y contratos públicos, en la sección «API pública»:

La API incluye nombres, tipos, errores, efectos, orden, formato y comportamiento documentado que consumidores pueden depender. No se limita a funciones exportadas. CLI, archivos, variables y mensajes parseados también forman contratos si se presentan como estables.

Ejemplo

Ejemplo de SE-474 — Versionado, compatibilidad y changelog (sección «Ejemplo profesional»):

El equipo escribe una política de versionado de la API de entregas: la API pública son los puntos finales documentados, sus parámetros, sus campos de respuesta, sus códigos de error y el orden de los listados cuando está especificado; el comportamiento no documentado no se promete. Cada solicitud de integración ejecuta el comparador de firmas y las pruebas de contrato, y quien revisa elige el nivel; si hay discrepancia, gana el mayor. Una funcionalidad deprecada emite un aviso en tiempo de ejecución desde la versión que la marca hasta la que la retira, con un mínimo de dos versiones menores y seis meses.

Errores y confusiones comunes

Errores que las clases asocian con este término (síntoma → causa → corrección):

  • El número de versión no dice nada — causa: API pública no definida. Corrección: declarar la API pública y lo que no se promete. (SE-474)

Límites y cuándo no aplica

Lo que las clases dicen sobre dónde deja de valer este término:

  • Una versión puede ser válida y aun así no comunicar nada si el autor no define qué es su API pública. (SE-110)
  • El versionado semántico asigna significado a los tres números de una versión: el mayor sube cuando hay cambios incompatibles de la API pública, el menor cuando se añade funcionalidad compatible y el parche cuando se corrige un error sin cambiar la API. (SE-474)
