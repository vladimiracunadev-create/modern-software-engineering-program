Definición

Ambas superficies llaman el mismo núcleo pero adaptan errores a su medio.

Definición de trabajo de SE-119 — Taller: empaquetar una capacidad reusable.

Por qué importa

En SE-119 — Taller: empaquetar una capacidad reusable, el tema «API y CLI coherentes» importa porque ambas superficies llaman el mismo núcleo pero adaptan errores a su medio.

Cómo funciona

Según SE-119 — Taller: empaquetar una capacidad reusable, en la sección «API y CLI coherentes»:

Ambas superficies llaman el mismo núcleo pero adaptan errores a su medio. La CLI no captura una excepción de dominio para devolver éxito; el SDK no imprime. Fixtures compartidos comprueban equivalencia observable.

Ejemplo

La clase no ilustra este término por separado; el ejemplo de su tema está en la sección «Ejemplo profesional» de SE-119 — Taller: empaquetar una capacidad reusable:

En el producto reutilizable con SDK y CLI, un release contiene contrato público, artefactos inmutables, dependencias, procedencia, ejemplos, errores y ruta de migración. La implementación de esta clase debe conservar ese contrato aunque cambie la forma interna. El caso profesional no pregunta únicamente si produce una salida: pregunta quién puede producirla, qué estado observa, cómo falla y qué rastro permite disputar una decisión incorrecta.

Errores y confusiones comunes

Las clases no registran un error exclusivo de este término. Los errores frecuentes del tema donde se enseña (SE-119 — Taller: empaquetar una capacidad reusable) son:

  • El paquete instalado no encuentra su archivo de datos — causa: falta package-data. Corrección: declararlo y comparar namelist() con una lista esperada.
  • ModuleNotFoundError solo en un entorno limpio — causa: dependencia usada pero no declarada. Corrección: declararla en dependencies y ejecutar la prueba de humo en un entorno vacío.

Límites y cuándo no aplica

Las clases no fijan un límite propio para este término. Los límites del tema donde se enseña (SE-119 — Taller: empaquetar una capacidad reusable) son: Las definiciones son operativas para el producto reutilizable con SDK y CLI. No convierten términos con historia más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final. El taller verifica una versión y un entorno principal. El proyecto siguiente construye una matriz de compatibilidad, plugin, automatización y procedencia para SDK+CLI.
