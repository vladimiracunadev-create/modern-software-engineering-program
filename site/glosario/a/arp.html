Definición

Protocolo IPv4 de resolución entre dirección IP y dirección de enlace.

Definición de trabajo de SE-038 — Ethernet, Wi-Fi, direccionamiento y redes locales.

Por qué importa

La clase donde se define, SE-038 — Ethernet, Wi-Fi, direccionamiento y redes locales, existe con este propósito: la clase existe para explicar entrega local mediante tramas, direcciones de enlace y resolución de vecinos.

Cómo funciona

Según SE-038 — Ethernet, Wi-Fi, direccionamiento y redes locales:

En IPv4, ARP resuelve una dirección de protocolo a una dirección de enlace en el dominio local. Para un destino remoto, el host resuelve la MAC de la puerta de enlace, no la del servidor. Una entrada vecina incompleta orienta el diagnóstico hacia enlace, VLAN o puerta de enlace.

Según SE-038 — Ethernet, Wi-Fi, direccionamiento y redes locales:

El conjunto de interfaces que reciben una trama enviada a la dirección de difusión (por ejemplo, una consulta ARP). Un enrutador separa dominios; un conmutador no, salvo que use VLAN. Acotarlos limita el ruido y el alcance de ciertos ataques.

Ejemplo

Ejemplo de SE-038 — Ethernet, Wi-Fi, direccionamiento y redes locales (sección «Ejemplo mínimo»):

Con una dirección local, máscara y destino remoto, determina cuál IP se consulta en la tabla de vecinos. Comprueba con arp -a, ip neigh o equivalente. Explica por qué no aparece la MAC del destino remoto.

Errores y confusiones comunes

Errores que las clases asocian con este término (síntoma → causa → corrección):

  • Suponer que ARP funciona entre subredes — causa: ARP solo opera dentro del dominio de difusión. Corrección: revisar el gateway y la tabla de rutas. (SE-038)

Límites y cuándo no aplica

Lo que las clases dicen sobre dónde deja de valer este término:

  • Si el destino está en el mismo prefijo, resuelve con ARP la dirección de enlace (MAC) *del destino*; si está en otro, resuelve la del *gateway* y le entrega la trama con el paquete IP intacto. (SE-038)
