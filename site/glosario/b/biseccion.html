Definición

Búsqueda binaria en el historial entre un commit bueno y uno malo para localizar el que introdujo un cambio.

Definición de trabajo de SE-194 — Commits atómicos, historial y recuperación.

El programa usa el término con matices según la clase; el sentido principal es el anterior y los demás lo precisan:

  • En SE-481 — Integración continua y feedback temprano: Búsqueda binaria del primer cambio defectuoso dividiendo repetidamente un conjunto de cambios.

Por qué importa

En SE-194 — Commits atómicos, historial y recuperación, el tema «Bisección» importa porque convierte un historial en una búsqueda con coste logarítmico si cada punto es comprobable.

Cómo funciona

Según SE-194 — Commits atómicos, historial y recuperación, en la sección «Bisección»:

git bisect hace una búsqueda binaria sobre el historial: dado un commit bueno y uno malo, prueba el del medio y descarta la mitad. Con N commits necesita unas log₂ N ejecuciones, de modo que 64 commits se resuelven en 6 y mil en 10. Funciona si cada punto se puede probar: un commit que no compila no es ni bueno ni malo y se omite (código 125 en bisect run), y si el defecto está junto a commits omitidos Git solo puede señalar un conjunto de candidatos.

Ejemplo

Ejemplo de SE-194 — Commits atómicos, historial y recuperación (sección «Ejemplo profesional»):

En la plataforma, cada cambio a penal.py va en un commit con una frase de resumen, un cuerpo que explica la regla de negocio afectada y un pie con el issue. Una prueba corta (pytest -q tests/test_penal.py) se ejecuta con git bisect run cuando una nota sale mal. El equipo exige que cada commit de una rama compile, de modo que la bisección no deba omitir puntos.

Errores y confusiones comunes

Errores que las clases asocian con este término (síntoma → causa → corrección):

  • La bisección no señala un solo commit — causa: hay un commit que no compila junto al defecto. Corrección: reordenar la rama para que cada paso compile y repetir. (SE-194)
  • Hay que leer cientos de líneas tras la bisección — causa: el commit culpable mezcla varias intenciones. Corrección: dividir los commits con git add -p antes de publicarlos. (SE-194)

Límites y cuándo no aplica

Lo que las clases dicen sobre dónde deja de valer este término:

  • El criterio práctico es el uso: debe poder revertirse sin arrastrar otra cosa, revisarse sin leer lo ajeno y localizarse con una bisección. (SE-194)
  • La transferencia está lograda cuando puedes explicar qué parte de la bisección dependía de poder probar cada punto, no cuando los comandos se parecen. (SE-194)
