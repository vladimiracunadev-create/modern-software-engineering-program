Definición

Fecha tras la cual un expediente deja de describir el canal actual.

Definición de trabajo de SE-480 — Proyecto: release firmado y recuperable.

Por qué importa

La clase donde se define, SE-480 — Proyecto: release firmado y recuperable, existe con este propósito: el proyecto existe para que construyas un canal de release completo y lo defiendas: que produzca un artefacto reproducible, lo acompañe de un SBOM y una procedencia, lo firme con una política de verificación explícita, permita volver atrás sin perder lo que importa y sobreviva a la pérdida del repositorio de releases y de una clave.

Cómo funciona

SE-480 — Proyecto: release firmado y recuperable no desarrolla este término en una sección propia. Lo usa como pieza de su tema: Las definiciones son operativas para la API de entregas. No convierten términos con una historia más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final.

Ejemplo

La clase no ilustra este término por separado; el ejemplo de su tema está en la sección «Ejemplo profesional» de SE-480 — Proyecto: release firmado y recuperable:

El equipo entrega un expediente con esta estructura. artefacto/ con el zip y su huella; sbom.json y procedencia.json ligados por huella; manifiesto.json y manifiesto.sig; esperados.json con la clave pública, el nombre, el constructor, el repositorio y la secuencia, con una nota sobre cómo se obtuvo cada valor; verificar.py y casos.py con las doce manipulaciones y los seis casos coherentes; registro-verificacion-windows.txt y registro-verificacion-ubuntu.txt; simulacros.md con los cuatro simulacros y su resultado; informe-verificacion.md con los tres estados; y LIMITES.md.

Errores y confusiones comunes

Las clases no registran un error exclusivo de este término. Los errores frecuentes del tema donde se enseña (SE-480 — Proyecto: release firmado y recuperable) son:

  • El cliente rechaza el retroceso — causa: se reinstala un bundle de secuencia menor. Corrección: republicar el contenido anterior con secuencia mayor.
  • Los hashes difieren entre sistemas — causa: campo de formato dependiente del sistema. Corrección: fijar el sistema de creación y normalizar el build.

Límites y cuándo no aplica

Las clases no fijan un límite propio para este término. Los límites del tema donde se enseña (SE-480 — Proyecto: release firmado y recuperable) son: Las definiciones son operativas para la API de entregas. No convierten términos con una historia más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final. Se ejecutó un proyecto de integración con un canal sintético (zip de 42 archivos, SBOM y procedencia simplificados, firmas Ed25519 de openssl), con verificación cruzada entre Windows 11 (CPython 3.12.9, OpenSSL 3.5.7) y Ubuntu bajo WSL2 (3.12.3, OpenSSL 3.0.13): las huellas y los rechazos fueron idénticos y los tiempos no.
