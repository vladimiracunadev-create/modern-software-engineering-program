Definición

Consulta en la que los datos se pasan separados de la instrucción SQL.

Definición de trabajo de SE-251 — Taller: reparar una API insegura e inconsistente.

El programa usa el término con matices según la clase; el sentido principal es el anterior y los demás lo precisan:

  • En SE-460 — Validación, codificación y clases de inyección: Sentencia SQL enviada al motor separada de los valores, de modo que los valores no pueden alterar su estructura.

Por qué importa

La clase donde se define, SE-251 — Taller: reparar una API insegura e inconsistente, existe con este propósito: el taller existe para que repares una API que funciona y está mal: diez defectos de seguridad y consistencia que ninguna prueba de camino feliz ve.

Cómo funciona

Según SE-251 — Taller: reparar una API insegura e inconsistente:

Con SQL concatenado, 3 de 12 cargas devuelven filas de otro usuario y 2 provocan un error del motor; con consulta parametrizada, 0 y 0. Los parámetros no sustituyen la autorización, y no protegen los nombres de columna u orden que vengan del cliente: esos se validan contra una lista cerrada.

Según SE-460 — Validación, codificación y clases de inyección:

Previenen la forma más común si se usan como están pensados (consultas parametrizadas, autoescape de plantillas). Fallan cuando se desactiva el autoescape, se arma una consulta a mano para un caso especial o se pasa un nombre de columna del cliente. Los frameworks reducen la superficie; no la eliminan.

Errores y confusiones comunes

Las clases no registran un error exclusivo de este término. Los errores frecuentes del tema donde se enseña (SE-251 — Taller: reparar una API insegura e inconsistente) son:

  • Todas las pruebas pasan y la API es vulnerable — causa: solo existen pruebas de camino feliz. Corrección: añadir suites de contrato y adversaria.
  • Un defecto reparado reaparece — causa: no hay prueba de regresión que falle sin la reparación. Corrección: reintroducir el defecto y comprobar que falla.

Límites y cuándo no aplica

Las clases no fijan un límite propio para este término. Los límites del tema donde se enseña (SE-251 — Taller: reparar una API insegura e inconsistente) son: Las definiciones son operativas para la plataforma de entregas. No convierten términos con una historia técnica más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final. Se ejecutaron tres experimentos con una API de laboratorio en proceso en Windows y Ubuntu (WSL2), con resultados idénticos. No se probó ningún servidor con red ni una API real, y nadie fue evaluado: los diez defectos y las tres suites son construcciones del autor. La siguiente clase integra los mecanismos en un servicio contractual y operable.
