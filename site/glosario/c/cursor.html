Definición

Posición reanudable dentro de una secuencia de eventos.

Definición de trabajo de SE-045 — Sockets, conexiones persistentes y tiempo real.

Por qué importa

La clase donde se define, SE-045 — Sockets, conexiones persistentes y tiempo real, existe con este propósito: la clase existe para modelar conexiones persistentes y tiempo real por estados, framing, heartbeat y backpressure.

Cómo funciona

Según SE-045 — Sockets, conexiones persistentes y tiempo real:

Si el productor supera al consumidor, una cola infinita solo aplaza el fallo. Se puede bloquear, muestrear, descartar con política o desconectar con cursor. Un ID monotónico o token de reanudación permite solicitar eventos posteriores, pero necesita retención y semántica de duplicados.

Según SE-045 — Sockets, conexiones persistentes y tiempo real:

La petición observable de extremo a extremo usa SSE para estados unidireccionales y entrega id por evento. El cliente reanuda con el último ID; el servidor conserva una ventana finita y responde explícitamente cuando el cursor expiró. Métricas separan conexiones abiertas, clientes lentos, bytes pendientes y reconexiones.

Errores y confusiones comunes

Las clases no registran un error exclusivo de este término. Los errores frecuentes del tema donde se enseña (SE-045 — Sockets, conexiones persistentes y tiempo real) son:

  • Latencia de ≈40 ms con conexión reutilizada — causa: dos escrituras pequeñas con Nagle y ACK retrasado. Corrección: escribir el mensaje completo o fijar TCP_NODELAY.
  • Memoria creciente en el emisor — causa: ignora la contrapresión y acumula una cola sin límite. Corrección: limitar la cola y definir política al llenarse.

Límites y cuándo no aplica

Las clases no fijan un límite propio para este término. Los límites del tema donde se enseña (SE-045 — Sockets, conexiones persistentes y tiempo real) son: Estas definiciones son operativas: precisan el uso dentro de la petición observable de extremo a extremo y deben leerse junto a las fuentes. No convierten un término histórico o dependiente de implementación en una garantía universal. Tiempo real aquí significa baja latencia percibida, no garantía hard real-time. Proxies pueden imponer timeouts. La siguiente clase enseña a capturar y medir sin violar privacidad.
