Definición

Código repetido que cambia por la misma razón y debería cambiarse junto.

Definición de trabajo de SE-306 — Code smells y diagnóstico contextual.

Por qué importa

La clase donde se define, SE-306 — Code smells y diagnóstico contextual, existe con este propósito: la clase existe para que trates un olor de código como una sospecha que se confirma o se descarta con contexto, y no como un defecto que un umbral declara: sabrás qué señala cada medida, qué falsas alarmas produce y qué pregunta hacer antes de refactorizar.

Cómo funciona

Según SE-306 — Code smells y diagnóstico contextual:

El código repetido es un problema si las copias deben cambiar juntas y una se olvida. Pero dos fragmentos parecidos que cambian por razones distintas no están duplicados en el sentido que importa: unirlos obliga a parametrizar las diferencias y la función compartida acumula ramas. La pregunta no es «¿se parecen?», sino «¿cambian por la misma razón?». La duplicación accidental se une; la coincidencia, no.

Ejemplo

Contexto concreto en el que aparece el término, de la sección «Ejemplo profesional» de SE-306 — Code smells y diagnóstico contextual:

El equipo no reduce el reporte a cero: lo clasifica. Para cada una de las doce funciones señaladas anota tres cosas en una tabla: si es lógica o datos, cuántas veces cambió en el último año según git log y quién la toca.

Errores y confusiones comunes

Ningún error de las clases nombra este término; estos son los errores frecuentes del tema donde se enseña (SE-306 — Code smells y diagnóstico contextual) son:

  • El tablero baja a cero y el código no mejora — causa: se optimizó la métrica y no el costo del cambio. Corrección: priorizar por historia de cambios y contexto.
  • Una plantilla o tabla de datos se parte en trozos — causa: la regla de largo no distingue datos de lógica. Corrección: excluir literales de datos de la regla.

Límites y cuándo no aplica

Ninguna clase fija un límite propio para este término; estos son los límites del tema donde se enseña (SE-306 — Code smells y diagnóstico contextual) son: Las definiciones son operativas para tarifas. No convierten términos con una historia más amplia en sinónimos y deben contrastarse con la bibliografía enlazada al final. Se ejecutaron tres análisis con código de ejemplo, un repositorio fijado por commit y datos sintéticos en Windows y Ubuntu (WSL2) con resultados idénticos. No se midió ningún proyecto de producción ni se validó ningún detector contra un conjunto etiquetado por varias personas; los umbrales, los parámetros de la simulación y las etiquetas son del autor. La siguiente clase ejecuta los tratamientos de forma segura apoyada en pruebas.
