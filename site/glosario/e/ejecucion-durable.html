Definición

Ejecución cuyo progreso se persiste para poder reanudarla tras una interrupción.

Definición de trabajo de SE-596 — Ejecución durable, reintentos e idempotencia.

Por qué importa

La clase donde se define, SE-596 — Ejecución durable, reintentos e idempotencia, existe con este propósito: la clase existe para que un sistema con LLM sobreviva a sus propias interrupciones sin repetir ni perder efectos.

Cómo funciona

Según SE-596 — Ejecución durable, reintentos e idempotencia:

Un workflow con modelos dura segundos o minutos y depende de procesos que se reinician (despliegues, escalado, fallos) y de servicios que fallan. Sin persistencia del progreso, cada interrupción obliga a empezar de cero: se pierde el tiempo, se vuelve a pagar el modelo y, peor, se repiten efectos. Los motores de ejecución durable (Temporal es un ejemplo documentado) resuelven esto persistiendo un historial de eventos y reanudando tras una caída reproduciendo el código hasta el punto donde se quedó. No hace falta un motor para entender el principio: un diario de pasos en una base transaccional ya lo ilustra.

Límites y cuándo no aplica

Las clases no fijan un límite propio para este término. Los límites del tema donde se enseña (SE-596 — Ejecución durable, reintentos e idempotencia) son: El diario es una base SQLite en memoria con un solo paso con efecto; el servicio externo es simulado y respeta la clave; la tormenta de reintentos usa clientes sincronizados sin cola ni limitación de tasa; no se probó ningún motor de ejecución durable ni ningún proveedor real. El siguiente paso, SE-597, trata cómo se mide un sistema con LLM: evaluaciones, ruido, jueces, trazas y puertas de release.
