Definición

Referencia a un archivo o a una ancla que no existe en el conjunto publicado.

Definición de trabajo de SE-212 — Docs as code, revisión y publicación.

Por qué importa

En SE-212 — Docs as code, revisión y publicación, el tema «Enlaces y anclas» importa porque un enlace roto es el defecto más frecuente y el más barato de detectar.

Cómo funciona

Según SE-212 — Docs as code, revisión y publicación:

Un enlace roto es la forma más frecuente de documentación que miente. Hay dos clases: el enlace a un archivo que se movió o renombró, y el enlace a un encabezado cuyo título cambió. La primera se detecta comprobando que la ruta exista; la segunda exige conocer cómo se genera la ancla de un encabezado, y ese algoritmo no está en la especificación de Markdown: cada renderizador convierte los títulos en identificadores con sus propias reglas (minúsculas, eliminación de signos, guiones por espacios, sufijos para duplicados). Un comprobador que use una regla distinta de la del sitio publicado dará falsas alarmas o dejará pasar enlaces rotos.

Errores y confusiones comunes

Las clases no registran un error exclusivo de este término. Los errores frecuentes del tema donde se enseña (SE-212 — Docs as code, revisión y publicación) son:

  • El linter emite cientos de avisos y nadie los lee — causa: no respeta los bloques de código. Corrección: usar un analizador de Markdown o ignorar las vallas de forma explícita.
  • Un cambio de título rompe enlaces internos sin aviso — causa: no se comprueban las anclas. Corrección: añadir la comprobación con la regla de ancla del sitio.

Límites y cuándo no aplica

Las clases no fijan un límite propio para este término. Los límites del tema donde se enseña (SE-212 — Docs as code, revisión y publicación) son: Las definiciones son operativas para el portal; no reemplazan las de las fuentes enlazadas abajo. Se ejecutaron tres experimentos con datos sintéticos en Windows y Ubuntu (WSL2) con resultados idénticos. No se midió ninguna canalización real ni el tiempo de revisión: el corpus de 60 archivos, la regla de ancla y el linter de tres reglas son construcciones del autor, y la construcción reproducible controla solo tres fuentes de variación.
