Definición

Número de elementos hijos que devuelve cada nivel de una consulta anidada.

Definición de trabajo de SE-243 — RPC, GraphQL y selección de interfaz.

Por qué importa

La clase donde se define, SE-243 — RPC, GraphQL y selección de interfaz, existe con este propósito: la clase existe para que elijas el estilo de interfaz (recursos HTTP, llamadas a procedimientos o consultas con selección de campos) por lo que cada uno cuesta y por lo que traslada al cliente o al servidor, y para que midas cuántos bytes, viajes y consultas a la base de datos produce una pantalla concreta en cada estilo.

Cómo funciona

Según SE-243 — RPC, GraphQL y selección de interfaz:

En una interfaz donde el cliente anida campos (curso { entregas { alumno { entregas { ... } } } }), el número de nodos crece como la fanout elevada a la profundidad. Con 20 elementos por nivel, profundidad 3 son 8 420 nodos y profundidad 6 más de 67 millones. Los límites típicos son de profundidad, de número de nodos estimado y de tiempo; cada uno rechaza algún tráfico legítimo. El límite se elige mirando las consultas que las pantallas hacen de verdad, no una cifra redonda.

Errores y confusiones comunes

Errores que las clases asocian con este término (síntoma → causa → corrección):

  • Un límite de profundidad rechaza consultas legítimas — causa: cifra elegida sin mirar el tráfico real. Corrección: medir la distribución de consultas y ponderar por fanout. (SE-243)

Límites y cuándo no aplica

Lo que las clases dicen sobre dónde deja de valer este término:

  • En una interfaz donde el cliente anida campos (curso { entregas { alumno { entregas { ... } } } }), el número de nodos crece como la fanout elevada a la profundidad. (SE-243)
