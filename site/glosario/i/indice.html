Definición

Instantánea que se prepara para el próximo commit; vive entre el árbol de trabajo y HEAD.

Definición de trabajo de SE-193 — Modelo de objetos y áreas de Git.

Por qué importa

La clase donde se define, SE-193 — Modelo de objetos y áreas de Git, existe con este propósito: la clase existe para que una persona deje de usar Git como una lista de comandos que a veces funciona y lo use como lo que es: una base de objetos direccionada por contenido, tres áreas donde un cambio puede estar y referencias que apuntan a commits.

Cómo funciona

Según SE-193 — Modelo de objetos y áreas de Git:

Un cambio puede estar en el árbol de trabajo (archivos en disco), en el índice (la instantánea que se prepara para el próximo commit) o en HEAD (el último commit). git add copia del árbol de trabajo al índice, git commit convierte el índice en un commit, git restore sobrescribe el árbol de trabajo desde el índice y git restore --staged sobrescribe el índice desde HEAD. El código de dos letras de git status --porcelain es una comparación por pares: la primera letra es índice contra HEAD y la segunda árbol de trabajo contra índice. Saber en qué área está un cambio es saber qué comando puede perderlo.

Según SE-193 — Modelo de objetos y áreas de Git:

Porque compara dos pares: la primera letra es el índice frente a HEAD y la segunda el árbol de trabajo frente al índice. AM significa agregado y modificado después de agregarlo.

Errores y confusiones comunes

Errores que las clases asocian con este término (síntoma → causa → corrección):

  • git diff aparece vacío pese a haber cambios — causa: los cambios ya están en el índice. Corrección: usar git diff --cached o git diff HEAD. (SE-193)

Límites y cuándo no aplica

Lo que las clases dicen sobre dónde deja de valer este término:

  • Dónde deja de valer: el diagrama describe archivos de texto sin conflictos, sin submódulos y sin assume-unchanged; durante una fusión conflictiva aparecen otros códigos (como UU) y el índice contiene tres versiones del mismo archivo. (SE-193)
