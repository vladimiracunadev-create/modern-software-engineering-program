Definición

Archivo JSON que declara el nombre, los iconos, la URL de inicio y el alcance de una aplicación instalable.

Definición de trabajo de SE-240 — Proyecto: aplicación web accesible y offline.

Por qué importa

La clase donde se define, SE-240 — Proyecto: aplicación web accesible y offline, existe con este propósito: el proyecto existe para que entregues una aplicación web de entregas accesible y utilizable sin conexión junto con un paquete de evidencia que otra persona pueda revisar: el manifiesto, las estrategias de caché, la tabla de estados, las URLs, las cabeceras, el presupuesto, el informe de accesibilidad con sus dos columnas y una matriz de pruebas con sus límites.

Cómo funciona

SE-240 — Proyecto: aplicación web accesible y offline usa este término dentro de otro tema, sin una sección propia. El contexto en que aparece: Las definiciones son operativas para esta clase y deben contrastarse con las especificaciones enlazadas al final.

Ejemplo

Contexto concreto en el que aparece el término, de la sección «Ejemplo profesional» de SE-240 — Proyecto: aplicación web accesible y offline:

La entrega del proyecto es un repositorio con la aplicación y una carpeta evidence/ que contiene: el manifiesto con su validación, la tabla de estrategias por recurso, la tabla de estados con un escenario por transición, la tabla de URLs con sus redirecciones, el informe de cabeceras generado contra un servidor local, el presupuesto con su comprobador, el informe de accesibilidad con las columnas «lo vio una regla» y «lo vio una persona» y la matriz de pruebas con su cobertura de pares y la lista de casos añadidos a mano.

Errores y confusiones comunes

Ningún error de las clases nombra este término; estos son los errores frecuentes del tema donde se enseña (SE-240 — Proyecto: aplicación web accesible y offline) son:

  • El manifiesto valida pero la aplicación no es instalable — causa: iconos inexistentes o de tamaño distinto al declarado. Corrección: comprobar que los archivos existen y miden lo declarado.
  • Una versión nueva no llega a los dispositivos — causa: sw.js servido con caché larga. Corrección: servirlo con no-cache y añadir una regla al comprobador.

Límites y cuándo no aplica

Ninguna clase fija un límite propio para este término; estos son los límites del tema donde se enseña (SE-240 — Proyecto: aplicación web accesible y offline) son: Las definiciones son operativas para esta clase y deben contrastarse con las especificaciones enlazadas al final. Se ejecutaron tres experimentos con datos sintéticos en Windows y Ubuntu (WSL2) con resultados idénticos. El manifiesto, el servidor de ocho respuestas y los 60 defectos de tres factores son construcciones del autor; no se instaló la aplicación, no se ejecutó un service worker en un navegador y no se evaluó con personas con discapacidad. Este proyecto cierra la Parte 19; la siguiente parte del programa cambia de superficie.
