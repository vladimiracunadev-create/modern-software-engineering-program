Definición

Criterio con número y unidad que permite decidir si un escenario se cumple.

Definición de trabajo de SE-433 — Modelos de calidad y atributos medibles.

Por qué importa

La clase donde se define, SE-433 — Modelos de calidad y atributos medibles, existe con este propósito: la clase existe para que conviertas una palabra como «rápido», «fiable» o «usable» en una promesa que se pueda comprobar: qué atributo de calidad importa, en qué situación, con qué estadístico, sobre qué ventana y con qué umbral.

Cómo funciona

Según SE-433 — Modelos de calidad y atributos medibles:

Un requisito como «el sistema debe ser seguro» no se puede probar. Un escenario de calidad lo vuelve comprobable con seis partes: la fuente del estímulo (una persona, otro sistema, un fallo), el estímulo (qué ocurre), el artefacto afectado (qué parte del sistema), el entorno (en qué condiciones: carga, datos, modo de operación), la respuesta esperada y la medida de la respuesta, que es lo que permite decidir. Cada parte elimina una ambigüedad: sin entorno, «p95 ≤ 300 ms» se cumple con un usuario y se rompe con doscientos; sin estadístico, «300 ms» puede significar media o máximo; sin unidad, el 300 puede ser milisegundos o segundos.

Ejemplo

La clase no ilustra este término por separado; el ejemplo de su tema está en la sección «Ejemplo profesional» de SE-433 — Modelos de calidad y atributos medibles:

El equipo de la plataforma elige cuatro atributos para el cierre de plazos: eficiencia de desempeño, fiabilidad, compatibilidad y capacidad de interacción. Para cada uno escribe un escenario completo. El de eficiencia dice: *fuente:* docente; *estímulo:* abre la lista de 300 entregas de un curso; *artefacto:* endpoint de listado; *entorno:* día laboral con 50 consultas por segundo y datos de producción del último mes; *respuesta:* se muestra la primera página;

Errores y confusiones comunes

Las clases no registran un error exclusivo de este término. Los errores frecuentes del tema donde se enseña (SE-433 — Modelos de calidad y atributos medibles) son:

  • El informe dice «cumple» y hay quejas — causa: ventana demasiado amplia o media como estadístico. Corrección: medir por ventana corta y con percentil.
  • Dos personas discuten si «300 ms» se cumple — causa: falta estadístico, entorno o unidad. Corrección: escribir el escenario con las seis partes.

Límites y cuándo no aplica

Las clases no fijan un límite propio para este término. Los límites del tema donde se enseña (SE-433 — Modelos de calidad y atributos medibles) son: Las definiciones son operativas para la API de entregas. No convierten términos con una historia más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final. Se ejecutaron tres experimentos con datos sintéticos en Windows y Ubuntu (WSL2) con resultados idénticos. No se midió ninguna API real, ningún usuario ni ningún sistema de producción; la proporción de peticiones lentas, el incidente del día 17, los diez escenarios base y los operadores de mutación son construcciones del autor, el verificador se escribió conociendo las mutaciones que lo evalúan y el texto de la norma no se reprodujo.
