Definición

Unidad de código con namespace propio.

Definición de trabajo de SE-068 — Módulos, interfaces y separación de responsabilidades.

El programa usa el término con matices según la clase; el sentido principal es el anterior y los demás lo precisan:

  • En SE-277 — WebAssembly y WASI: Unidad compilada de WebAssembly (binario .wasm o texto .wat).

Por qué importa

La clase donde se define, SE-068 — Módulos, interfaces y separación de responsabilidades, existe con este propósito: la clase existe para separar módulos por responsabilidades y contratos estables, no por tamaño de archivo.

Cómo funciona

Según SE-068 — Módulos, interfaces y separación de responsabilidades:

Un módulo es código cargable con su namespace. La primera importación ejecuta su nivel superior y se guarda en sys.modules; por eso el nivel superior evita I/O inesperado. if __name__ == '__main__' separa ejecución directa de importación.

Según SE-068 — Módulos, interfaces y separación de responsabilidades:

La CLI diagnóstica expone choose_next como interfaz de dominio, estable y sin efectos. La CLI convierte excepciones de frontera a códigos de salida. Los módulos no imprimen al importarse y el paquete puede ejecutarse con python -m diagnostic_cli.

Errores y confusiones comunes

Errores que las clases asocian con este término (síntoma → causa → corrección):

  • ImportError: partially initialized module — causa: importación circular con from … import. Corrección: extraer lo común a un tercer módulo o invertir la dependencia. (SE-068)
  • importar un módulo abre archivos o red — causa: efectos al nivel del módulo. Corrección: mover los efectos a main() o a una función llamada explícitamente. (SE-068)

Límites y cuándo no aplica

Lo que las clases dicen sobre dónde deja de valer este término:

  • domain.py (82 líneas) no importa ningún módulo local; (SE-068)
  • Contar líneas no sirve: el laboratorio tiene módulos de 82 a 110 líneas porque cada uno cambia por una sola razón. (SE-068)
