Definición

Orden de ejecución que respeta todas las dependencias.

Definición de trabajo de SE-364 — Transformación y orquestación idempotente con backfills.

Por qué importa

La clase donde se define, SE-364 — Transformación y orquestación idempotente con backfills, existe con este propósito: la clase existe para que construyas transformaciones de datos que se puedan ejecutar de nuevo sin miedo: tras un fallo a mitad, tras un reintento automático, tras corregir un dato de origen o tras descubrir un error de hace un mes.

Cómo funciona

Según SE-364 — Transformación y orquestación idempotente con backfills:

Las tareas forman un grafo acíclico dirigido: cada tarea depende de otras. El laboratorio tiene nueve tareas (dos crudas, dos intermedias, una dimensión, un hecho, dos marts y un informe). Un orden topológico válido es: raw_customers, raw_orders, stg_customers, dim_customer, stg_orders, fact_sales, mart_city, mart_daily, report_exec. Si cambia raw_orders hay que recalcular 5 tareas; si cambia raw_customers, 6; si cambia fact_sales, 3. Sin el grafo, la corrección se propaga a mano y se olvida un mart. Un ciclo no tiene orden y se rechaza: un orquestador que lo acepta no termina.

Límites y cuándo no aplica

Las clases no fijan un límite propio para este término. Los límites del tema donde se enseña (SE-364 — Transformación y orquestación idempotente con backfills) son: Las particiones, el fallo y los retrasos son construcciones del autor; no se ejecutó ningún orquestador ni se midió una carga con millones de filas, y el tiempo de reemplazar una partición grande no se midió. El resultado «reemplazar y fusionar son idempotentes» vale con transacción o con una clave bien definida, y se comprobó solo para esos casos.
