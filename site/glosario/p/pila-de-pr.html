Definición

Serie de pull requests encadenados donde cada uno parte de la rama del anterior.

Definición de trabajo de SE-196 — Pull requests y revisión basada en riesgo.

Por qué importa

La clase donde se define, SE-196 — Pull requests y revisión basada en riesgo, existe con este propósito: la clase existe para que una revisión de cambios sea una decisión sobre dónde poner la atención limitada de una persona y no un trámite ni una lectura lineal de un diff.

Cómo funciona

Según SE-196 — Pull requests y revisión basada en riesgo:

La capacidad de atención de una persona es finita y un cambio grande se revisa por encima. Dividir no es solo partir un diff: cada parte debe tener sentido por sí misma, compilar y poder revertirse sola. Un PR de refactor mecánico (un renombre masivo) puede ser grande y revisable si se separa del cambio de lógica; uno de lógica no. Una pila de PR encadenados reduce lo que se lee pero tiene un costo: corregir el primero obliga a reapilar los demás.

Ejemplo

La clase no ilustra este término por separado; el ejemplo de su tema está en la sección «Ejemplo profesional» de SE-196 — Pull requests y revisión basada en riesgo:

En la plataforma, la plantilla de PR pide qué cambia, por qué, cómo se probó y qué archivos merecen más atención. Un flujo de integración continua ejecuta formato, pruebas, análisis estático y búsqueda de secretos antes de asignar revisora. El CODEOWNERS, tema de SE-199, añade como revisor obligatorio al equipo dueño de las migraciones cuando un PR toca migraciones/. La revisora abre primero los archivos marcados como riesgo alto, lee la descripción y, tras las correcciones, usa range-diff para ver lo cambiado.

Errores y confusiones comunes

Las clases no registran un error exclusivo de este término. Los errores frecuentes del tema donde se enseña (SE-196 — Pull requests y revisión basada en riesgo) son:

  • Comentarios de estilo y defectos que se escapan — causa: la lectura sigue el orden del diff. Corrección: ordenar por riesgo y automatizar el estilo.
  • Hay que releer todo tras cada corrección — causa: la rama se reescribió sin mostrar lo cambiado. Corrección: usar range-diff o commits de corrección.

Límites y cuándo no aplica

Las clases no fijan un límite propio para este término. Los límites del tema donde se enseña (SE-196 — Pull requests y revisión basada en riesgo) son: Las definiciones son operativas para la plataforma de entregas. No convierten términos con historia más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final. Se ejecutaron tres experimentos con repositorios temporales y datos sintéticos en Windows y Ubuntu (WSL2) con resultados idénticos. Las densidades de defectos y el presupuesto de lectura son supuestos del autor, el criterio por riesgo se evaluó con los mismos tipos que usó el generador y no se midió a ningún revisor ni un proyecto real.
