Definición

Una plataforma combina capacidades, políticas, interfaces y operación para que otros construyan.

Definición de trabajo de SE-109 — Biblioteca, framework, runtime, plataforma y SDK.

El programa usa el término con matices según la clase; el sentido principal es el anterior y los demás lo precisan:

  • En SE-025 — Windows, Linux, macOS y sus modelos operativos: Combinación relevante de hardware, sistema, versión, políticas y capacidades; no solo un nombre comercial.

Por qué importa

En SE-109 — Biblioteca, framework, runtime, plataforma y SDK, el tema «Plataforma» importa porque una plataforma combina capacidades, políticas, interfaces y operación para que otros construyan.

Cómo funciona

Según SE-109 — Biblioteca, framework, runtime, plataforma y SDK, en la sección «Plataforma»:

Una plataforma combina capacidades, políticas, interfaces y operación para que otros construyan. No es solo un conjunto de librerías ni una marca. Ownership, SLO, autenticación, cuotas y soporte forman parte de su producto.

Ejemplo

Ejemplo de SE-109 — Biblioteca, framework, runtime, plataforma y SDK (sección «Preguntas frecuentes»):

No, es otra dependencia con su propio ciclo de versiones. En este programa se midió con CPython 3.12.9 y 3.12.3; un consumidor con otro intérprete puede ver otros módulos cargados y otros tiempos. El contrato debe declarar versiones y plataformas soportadas.

Errores y confusiones comunes

Errores que las clases asocian con este término (síntoma → causa → corrección):

  • El producto se anuncia como «plataforma» pero no tiene responsable ni SLO — causa: se confundió conjunto de librerías con plataforma. Corrección: escribir propiedad, soporte, cuotas y política de cambios, o llamarlo biblioteca. (SE-109)
  • “Linux” aparece como una sola plataforma uniforme — causa: se confundió kernel con distribución y espacio de usuario. Corrección: registrar kernel, distribución, versión y herramientas relevantes por separado. (SE-025)

Límites y cuándo no aplica

Lo que las clases dicen sobre dónde deja de valer este término:

  • Un intérprete limpio parte con 25 módulos en Windows y 23 en Linux, así que el costo de asyncio es 9,0 veces el de json en Windows y 4,9 en Linux: la diferencia entre plataformas es mayor que la diferencia entre algunos módulos, razón para comparar razones y no milisegundos. (SE-109)
