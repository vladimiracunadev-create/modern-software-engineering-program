Definición

Valor que representa éxito o fallo esperado.

Definición de trabajo de SE-065 — Errores, excepciones y resultados explícitos.

Por qué importa

La clase donde se define, SE-065 — Errores, excepciones y resultados explícitos, existe con este propósito: la clase existe para distinguir error esperado, excepción, resultado explícito y fallo irrecuperable.

Cómo funciona

Según SE-065 — Errores, excepciones y resultados explícitos, en la sección «Resultado explícito»:

Cuando ausencia o rechazo es parte esperada del dominio, un resultado etiquetado evita usar excepciones como control ordinario. Python puede usar una estructura {'ok': False, 'error': ...} o tipos propios; Rust usa Result<T,E>. El contrato debe impedir estados ambiguos con valor y error simultáneos.

Errores y confusiones comunes

Ningún error de las clases nombra este término; estos son los errores frecuentes del tema donde se enseña (SE-065 — Errores, excepciones y resultados explícitos) son:

  • el programa no responde a Ctrl+C — causa: except: o except BaseException: captura KeyboardInterrupt. Corrección: capturar clases concretas; Exception solo en el borde.
  • un error desaparece sin rastro — causa: except …: pass o return dentro de finally. Corrección: manejar solo lo recuperable y registrar o relanzar.

Límites y cuándo no aplica

Ninguna clase fija un límite propio para este término; estos son los límites del tema donde se enseña (SE-065 — Errores, excepciones y resultados explícitos) son: Estas definiciones describen el uso concreto en la CLI diagnóstica. Cuando Python permita varias conductas, el contrato del programa elige una y la hace visible con validación y pruebas. La taxonomía no evita todos los defectos ni reemplaza logs seguros.
