Definición

Crecimiento exponencial del tiempo de una expresión regular al explorar divisiones alternativas de una entrada.

Definición de trabajo de SE-162 — Esquemas de datos y validación.

Por qué importa

La clase donde se define, SE-162 — Esquemas de datos y validación, existe con este propósito: la clase existe para describir con un esquema la forma que deben tener los datos que cruzan una frontera, y para saber qué errores atrapa ese esquema, cuáles no, y qué ataques abre el propio acto de validar.

Cómo funciona

SE-162 — Esquemas de datos y validación usa este término dentro de otro tema, sin una sección propia. El contexto en que aparece: Las definiciones son operativas para la plataforma de entregas. No convierten términos con historia más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final.

Ejemplo

Contexto concreto en el que aparece el término, de la sección «Ejemplo profesional» de SE-162 — Esquemas de datos y validación:

En la plataforma, el esquema del documento de entrega vive en un archivo versionado junto al código del consumidor y del productor. La frontera valida primero la longitud y el tamaño del documento, después la forma con el esquema y por último las reglas entre campos con funciones con nombre (fin_no_anterior_a_inicio, prorroga_no_supera_tope). Cada rechazo devuelve el campo, la regla y un código estable, sin repetir valores sensibles. Los patrones se revisan por cuantificadores anidados y se miden con una entrada hostil en integración continua.

Errores y confusiones comunes

Ningún error de las clases nombra este término; estos son los errores frecuentes del tema donde se enseña (SE-162 — Esquemas de datos y validación) son:

  • Una nota true se almacena como 1 — causa: el validador usa isinstance(x, int) y bool es subclase de int. Corrección: excluir booleanos explícitamente y probar tipos con casos de cada lenguaje.
  • Un campo opcional mal escrito se descarta en silencio — causa: esquema abierto sin comprobación de campos conocidos. Corrección: cerrar el esquema donde la evolución lo permita o registrar los campos desconocidos.

Límites y cuándo no aplica

Ninguna clase fija un límite propio para este término; estos son los límites del tema donde se enseña (SE-162 — Esquemas de datos y validación) son: Las definiciones son operativas para la plataforma de entregas. No convierten términos con historia más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final. Se ejecutaron tres experimentos con datos sintéticos en Windows y Ubuntu (WSL2): conteos idénticos y tiempos distintos. No se usó una biblioteca de validación completa, las fechas se sortearon de forma independiente y no se midió ninguna integración real. La siguiente clase coloca este esquema dentro de contratos de interfaz y de eventos.
