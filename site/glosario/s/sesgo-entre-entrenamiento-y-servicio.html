Definición

Diferencia entre cómo se calcula o se distribuye una característica en cada entorno.

Definición de trabajo de SE-602 — Datos de entrenamiento, etiquetas y feature stores.

El programa usa el término con matices según la clase; el sentido principal es el anterior y los demás lo precisan:

  • En SE-601 — Ciclo de vida de ML y por qué falla en producción: Diferencia entre cómo se calculan o distribuyen las entradas en cada entorno.

Por qué importa

La clase donde se define, SE-602 — Datos de entrenamiento, etiquetas y feature stores, existe con este propósito: la clase existe para que trates los datos de un modelo como un producto de ingeniería con defectos propios, y no como una materia prima que «ya viene».

Cómo funciona

Según SE-602 — Datos de entrenamiento, etiquetas y feature stores:

La práctica más robusta contra el sesgo entre entrenamiento y servicio es entrenar con las características tal como el servicio las registró al decidir, en vez de recalcularlas después. Resuelve la unión puntual y la paridad de una vez, con el costo de almacenar cada vector de entrada. En *Avisos*, 20 000 decisiones diarias con seis características de ocho bytes suman unos 1,0 MB por día antes de comprimir; guardar la entrada de cada decisión rara vez es el costo que impide hacerlo. Lo que sí exige es una política de retención y de datos personales, que SE-610 retoma.

Límites y cuándo no aplica

Las clases no fijan un límite propio para este término. Los límites del tema donde se enseña (SE-602 — Datos de entrenamiento, etiquetas y feature stores) son: La fuga, el ruido, la unión y las definiciones alternativas son construcciones del autor sobre datos sintéticos de seis características; los números muestran mecanismos, no la frecuencia ni el costo de estos defectos en ningún sistema real. No se evaluó ningún almacén de características. El siguiente paso, SE-603, pregunta si el entrenamiento sobre estos datos se puede repetir y cuánto de la diferencia entre dos corridas es azar.
