Definición

Modelo en el que un mismo programa lo ejecutan muchos hilos sobre datos distintos.

Definición de trabajo de SE-280 — GPU y aceleradores: modelo de ejecución.

Por qué importa

La clase donde se define, SE-280 — GPU y aceleradores: modelo de ejecución, existe con este propósito: la clase existe para que puedas razonar sobre un acelerador sin haberlo tocado y sin creer que «la GPU es una CPU más rápida».

Cómo funciona

Según SE-280 — GPU y aceleradores: modelo de ejecución:

Una CPU moderna está diseñada para ejecutar pocos hilos muy rápido: cachés grandes, predicción de saltos, ejecución fuera de orden. Un acelerador de tipo GPU está diseñado para ejecutar *muchísimos* hilos simples a la vez y tolerar la latencia de memoria cambiando de hilo en lugar de esperarla. El modelo de programación (SIMT, un mismo programa y muchos hilos) pide escribir lo que hace *un* hilo para *un* dato; el sistema lo lanza sobre todos. Por eso el trabajo que se traslada bien es el que tiene la forma de «aplicar la misma función a cada elemento» o «combinar elementos con una operación asociativa». Límites y cuándo no aplica

Las clases no fijan un límite propio para este término. Los límites del tema donde se enseña (SE-280 — GPU y aceleradores: modelo de ejecución) son: No se ejecutó ningún núcleo en una GPU; las medidas son de CPU y NumPy y la divergencia es un modelo con semilla 48. El siguiente paso, SE-281, lleva el modelo al terreno económico: qué rendimiento y qué costo por petición se obtienen según el tamaño del lote, la precisión y la utilización, con parámetros del autor para los precios.
