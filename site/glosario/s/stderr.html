Definición

Stream de diagnóstico.

Definición de trabajo de SE-072 — Proyecto: herramienta de línea de comandos probada.

El programa usa el término con matices según la clase; el sentido principal es el anterior y los demás lo precisan:

  • En SE-029 — Terminales, shells y composición de comandos: Canal convencional de diagnóstico.

Por qué importa

La clase donde se define, SE-072 — Proyecto: herramienta de línea de comandos probada, existe con este propósito: la clase existe para integrar CLI, validación, archivos, pruebas y diagnóstico en una herramienta reproducible.

Cómo funciona

Según SE-072 — Proyecto: herramienta de línea de comandos probada:

Nombre, subcomandos, opciones, stdin/stdout/stderr y códigos de salida son interfaz pública. --help incluye propósito y ejemplos; argumentos inválidos fallan antes de modificar estado. La salida humana y JSON se seleccionan explícitamente.

Según SE-072 — Proyecto: herramienta de línea de comandos probada:

La CLI diagnóstica acepta un paquete del modelo de decisión diagnóstica, genera recomendación y explica cobertura/costo. --dry-run valida sin escribir; JSON va a stdout y diagnóstico a stderr. La entrega incluye 12+ pruebas, fixtures pequeños, README y evidencia reproducible en Windows y Unix o una matriz honesta de lo no ejecutado.

Errores y confusiones comunes

Errores que las clases asocian con este término (síntoma → causa → corrección):

  • el consumidor falla al leer stdout — causa: mensajes de diagnóstico mezclados con los datos. Corrección: stdout solo datos; stderr solo diagnóstico. (SE-072)
  • Un archivo JSON contiene mensajes de progreso — causa: stdout y stderr no tienen roles definidos. Corrección: reservar stdout para datos y stderr para diagnóstico. (SE-029)

Límites y cuándo no aplica

Lo que las clases dicen sobre dónde deja de valer este término:

  • La ruta feliz produjo 0 y un JSON de 616 bytes (status: resolved, candidatos [tls]) en stdout, sin una línea en stderr. (SE-072)
