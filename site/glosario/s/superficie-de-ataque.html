Definición

Conjunto de puntos por los que una persona puede intentar interactuar con un sistema de forma no prevista.

Definición de trabajo de SE-251 — Taller: reparar una API insegura e inconsistente.

Por qué importa

La clase donde se define, SE-251 — Taller: reparar una API insegura e inconsistente, existe con este propósito: el taller existe para que repares una API que funciona y está mal: diez defectos de seguridad y consistencia que ninguna prueba de camino feliz ve.

Cómo funciona

SE-251 — Taller: reparar una API insegura e inconsistente usa este término dentro de otro tema, sin una sección propia. El contexto en que aparece: Las definiciones son operativas para la plataforma de entregas. No convierten términos con una historia técnica más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final.

Ejemplo

Contexto concreto en el que aparece el término, de la sección «Ejemplo profesional» de SE-251 — Taller: reparar una API insegura e inconsistente:

El equipo recibe la API con los diez defectos y trabaja en seis pasos: escribe las tres suites; mide qué falla; repara por orden de riesgo (D3, D1, D10, D2, D4, D8, D6, D7, D9, D5); añade una prueba de regresión para cada reparación; reintroduce cada defecto y registra qué suite lo detecta; y publica la lista de defectos dormidos. Compara con el original en tres casos: un usuario normal, un integrador con un script y alguien que prueba la API sin permiso.

Errores y confusiones comunes

Ningún error de las clases nombra este término; estos son los errores frecuentes del tema donde se enseña (SE-251 — Taller: reparar una API insegura e inconsistente) son:

  • Todas las pruebas pasan y la API es vulnerable — causa: solo existen pruebas de camino feliz. Corrección: añadir suites de contrato y adversaria.
  • Un defecto reparado reaparece — causa: no hay prueba de regresión que falle sin la reparación. Corrección: reintroducir el defecto y comprobar que falla.

Límites y cuándo no aplica

Ninguna clase fija un límite propio para este término; estos son los límites del tema donde se enseña (SE-251 — Taller: reparar una API insegura e inconsistente) son: Las definiciones son operativas para la plataforma de entregas. No convierten términos con una historia técnica más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final. Se ejecutaron tres experimentos con una API de laboratorio en proceso en Windows y Ubuntu (WSL2), con resultados idénticos. No se probó ningún servidor con red ni una API real, y nadie fue evaluado: los diez defectos y las tres suites son construcciones del autor. La siguiente clase integra los mecanismos en un servicio contractual y operable.
