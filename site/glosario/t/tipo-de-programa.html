Definición

Categoría que fija dónde se engancha, qué recibe y qué ayudantes puede usar.

Definición de trabajo de SE-279 — eBPF: observabilidad, red y seguridad en el kernel.

Por qué importa

La clase donde se define, SE-279 — eBPF: observabilidad, red y seguridad en el kernel, existe con este propósito: la clase existe para que entiendas eBPF como lo que es en la práctica: un mecanismo para cargar programas pequeños en el núcleo de Linux sin recompilarlo ni reiniciarlo, con un verificador que decide antes de ejecutar si el programa es seguro.

Cómo funciona

Según SE-279 — eBPF: observabilidad, red y seguridad en el kernel:

Un programa eBPF es una secuencia de instrucciones de 8 bytes (con una excepción de 16 para cargar constantes de 64 bits) para una máquina de registros: diez registros de 64 bits, r0 para el valor de retorno, r1 a r5 para los argumentos, r10 como puntero de solo lectura a una pila de 512 bytes. Se carga con la llamada de sistema bpf y la orden BPF_PROG_LOAD, que recibe el tipo de programa, las instrucciones, la licencia y un búfer donde el núcleo escribe el registro del verificador. Si el verificador acepta, el núcleo compila el programa a instrucciones nativas (compilación JIT, habilitada en el núcleo del laboratorio) y devuelve un descriptor de archivo.

Límites y cuándo no aplica

Lo que las clases dicen sobre dónde deja de valer este término:

  • Comprueba que ningún registro se lea antes de escribirse, que cada acceso a memoria caiga dentro de la región a la que el puntero tiene derecho, que todo camino termine en una salida, que solo se llamen ayudantes permitidos para ese tipo de programa y que el número de instrucciones exploradas no supere un límite. (SE-279)
