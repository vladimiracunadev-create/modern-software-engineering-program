Definición

Credencial firmada que transporta afirmaciones sobre un sujeto y su vigencia.

Definición de trabajo de SE-245 — Autenticación, autorización y contexto.

Por qué importa

En SE-245 — Autenticación, autorización y contexto, el tema «Autenticación» importa porque sin una verificación completa, un token falsificado o ajeno se acepta como si fuera válido.

Cómo funciona

Según SE-245 — Autenticación, autorización y contexto:

Autenticar es establecer *quién* hace la solicitud. Un token firmado transporta un sujeto y unas afirmaciones, y su verificación exige varias comprobaciones: que el algoritmo sea el esperado (no el que declara la cabecera), que la firma coincida con la clave del emisor, que el emisor y la audiencia sean los de esta API, y que la hora actual esté entre nbf y exp. Cada comprobación omitida es un ataque: alg: none evita la firma, un token expirado se acepta para siempre, uno de otra audiencia funciona en esta API.

Según SE-245 — Autenticación, autorización y contexto:

La plataforma verifica cada token con algoritmo fijado, emisor, audiencia y vigencia; extrae sujeto y rol del token; y aplica una política en tabla con denegación por defecto. Cada lectura de una entrega comprueba que el sujeto sea su dueño o un docente del curso, y devuelve 404 si no. El contexto (sujeto, curso, correlación) viaja a la capa de datos y al trabajo diferido. Compara este diseño con el original en tres casos: un token de otra API, un identificador filtrado en un registro y un rol nuevo (ayudante) que se añade a la tabla.

Errores y confusiones comunes

Errores que las clases asocian con este término (síntoma → causa → corrección):

  • Un token vencido sigue funcionando — causa: el verificador no comprueba exp. Corrección: comprobar vigencia con un margen de reloj acotado. (SE-245)
  • Un token de otra API funciona aquí — causa: no se comprueba la audiencia. Corrección: exigir audiencia y emisor. (SE-245)
  • El rol llega en un encabezado del cliente — causa: contexto tomado de datos controlados por el cliente. Corrección: derivar rol y sujeto del token verificado. (SE-245)

Límites y cuándo no aplica

Lo que las clases dicen sobre dónde deja de valer este término:

  • Un token firmado transporta un sujeto y unas afirmaciones, y su verificación exige varias comprobaciones: que el algoritmo sea el esperado (no el que declara la cabecera), que la firma coincida con la clave del emisor, que el emisor y la audiencia sean los de esta API, y que la hora actual esté entre nbf y exp. (SE-245)
  • Prueba: repite la solicitud con un token de otro alumno y con un token falso, y observa que las dos devuelven lo mismo. (SE-245)
