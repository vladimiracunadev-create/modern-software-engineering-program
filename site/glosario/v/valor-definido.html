Definición

Valor que una fuente aporta según el criterio documentado (presente, no vacío, etc.).

Definición de trabajo de SE-219 — Configuración, flags, archivos y precedencia.

Por qué importa

La clase donde se define, SE-219 — Configuración, flags, archivos y precedencia, existe con este propósito: la clase existe para decidir de dónde obtiene una herramienta cada valor —valor por defecto, archivo, variable de entorno o flag—, en qué orden se imponen y cómo se comprueba que ese orden se cumple también en los casos extraños: valores vacíos, booleanos escritos de varias formas y secretos.

Cómo funciona

SE-219 — Configuración, flags, archivos y precedencia usa este término dentro de otro tema, sin una sección propia. El contexto en que aparece: Las definiciones son operativas para la herramienta notas. No convierten términos con historia más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final.

Ejemplo

Contexto concreto en el que aparece el término, de la sección «Ejemplo profesional» de SE-219 — Configuración, flags, archivos y precedencia:

notas carga el archivo de usuario (~/.config/notas/config.ini o el equivalente de Windows), después el del proyecto, lee las variables con prefijo NOTAS_, interpreta los booleanos con el analizador estricto y aplica los flags. El comando notas config --efectiva imprime cada opción con su valor y su fuente, con los secretos enmascarados. El token se lee de un archivo (--token-file) o de la entrada estándar; no existe --token.

Errores y confusiones comunes

Ningún error de las clases nombra este término; estos son los errores frecuentes del tema donde se enseña (SE-219 — Configuración, flags, archivos y precedencia) son:

  • --limite 0 se ignora — causa: se escribió if flag: en lugar de is not None. Corrección: distinguir ausencia de valor falso.
  • NOTAS_VERBOSE=false activa el modo detallado — causa: se aplicó bool() a una cadena. Corrección: interpretación estricta con conjunto cerrado.

Límites y cuándo no aplica

Ninguna clase fija un límite propio para este término; estos son los límites del tema donde se enseña (SE-219 — Configuración, flags, archivos y precedencia) son: Las definiciones son operativas para la herramienta notas. No convierten términos con historia más amplia en sinónimos y deben contrastarse con la documentación primaria enlazada al final. Se ejecutaron tres experimentos con datos sintéticos en Windows y Ubuntu (WSL2) con resultados idénticos salvo el mecanismo de lectura del secreto. Los seis defectos, los valores de cada capa, el conjunto de booleanos aceptados y el secreto falso son supuestos del autor; no se midió ningún despliegue real. La siguiente clase pregunta qué significa para quien invoca que la configuración o la ejecución fallen: los códigos de salida.
