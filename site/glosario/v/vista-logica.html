Definición

Vista que muestra módulos y las dependencias permitidas entre ellos.

Definición de trabajo de SE-326 — Vistas lógica, runtime, datos y despliegue.

Por qué importa

En SE-326 — Vistas lógica, runtime, datos y despliegue, el tema «Vista lógica» importa porque gobierna la modificabilidad: quién puede depender de quién.

Cómo funciona

Según SE-326 — Vistas lógica, runtime, datos y despliegue, en la sección «Vista lógica»:

La vista lógica muestra módulos o componentes y las dependencias *permitidas* entre ellos. Responde a «¿qué puedo cambiar sin romper a quién?» y gobierna la modificabilidad. Su defecto característico es que declara lo permitido, no lo que ocurre: con el tiempo, el código acumula dependencias que nadie dibujó. Por eso conviene tratarla como una regla que se verifica contra el código o contra las trazas, no como un dibujo que se acepta. Una arista declarada que nunca se usa es otra señal: o el diagrama está viejo o hay código muerto.

Errores y confusiones comunes

Errores que las clases asocian con este término (síntoma → causa → corrección):

  • El código tiene dependencias que nadie dibujó — causa: la vista lógica declara lo permitido y no se verifica. Corrección: comparar con trazas o con el código en cada cambio. (SE-326)

Límites y cuándo no aplica

Lo que las clases dicen sobre dónde deja de valer este término:

  • La vista lógica muestra módulos o componentes y las dependencias *permitidas* entre ellos. (SE-326)
